# Vector Rush：视觉与动态验收表

这张表用于同一段完整体验的评审。技术能力存在、物体数量增加或单张参考图好看，都不等于该项通过。已有道路与尾焰候选仅作为对照。

| 维度 | 用户的目标 | 需要看到的成品表现 | 不通过的信号 |
| --- | --- | --- | --- |
| 城市资产 | 多样、密集，有赛博朋克城市感 | 近处有构造，中景建筑轮廓/体量有差异，远景交叠；裙楼、交通结构和标识把城市连起来 | 同一种楼换高度；满墙同样小窗；孤立楼块和大面积无意义空隙 |
| 城市活跃感 | 环境有生命 | 有选择的屏幕、灯点变化与远景装饰交通，随驾驶产生有层次的视差 | 所有窗同步闪烁；每块屏都抢眼；用随机漂浮粒子填空 |
| 霓虹与材质 | 发光物体有灯芯、光晕和颜色 | 发光轮廓保留形状，局部光晕柔和，路面/船身有合理受光；暗面仍有材质区别 | 纯亮色条；光晕吞掉箭头/窗灯；全路变成自发光色块 |
| 雾与远景 | 远楼不必清晰，但城市有规模 | 对比度随距离变化，层叠轮廓和灯点穿过空气，近路和弯道清楚 | 全屏灰雾；所有楼同样模糊；用雾掩盖近景资产不足 |
| 道路与护栏 | 左右倾斜、曲面平顺、指引丰富 | 相邻路段的法线/倾斜连续，护栏与箭头沿路贴合；近景设施能提供速度参照 | 平板折接、法线接缝；只晃镜头；悬空标牌；没有用途的霓虹堆积 |
| 速度感 | 加速明显更快、更有力度 | 近景流动、有限 FOV/阻尼与模糊协同，boost 起落清楚；能持续读懂前方路线 | 只增加数值；持续抖动；全屏涂抹；镜头和船身滚转叠加失控 |
| 飞船状态 | 能量变化影响整个船身 | 同一飞船在已有 boost 激活/持续/释放时有可辨认的材质与局部轮廓变化 | 只有尾焰变长；船完全消失；无依据增加护盾/变形玩法 |
| 尾焰 | 大、饱满、快速喷射，有粒子层次 | 紧贴喷口的亮核、翻卷主体、细长亮粒与逐渐散开的尾流；弯道、近镜头和释放稳定 | 交叉片边、静态光带、均匀水柱、大团前景光斑、串珠或脱离喷口 |
| 碰撞 | 有瞬时爆发和接触感 | 真实接触点的闪光、沿滑动方向的金橙火花、大小不同的亮点；擦墙持续发射，离墙结束 | 每次相同大爆炸；粒子从船中心冒出；碰撞后继续喷火花；持续遮挡道路 |
| 字体与 UI | 有赛车风格，随驾驶事件变化 | 显示数字与小字有明确搭配，已有排名/boost/碰撞提示有一致的运动节奏，菜单继承相同语言 | 通用面板感；每项都放大；文字一直闪；新增没有对应玩法的数据 |
| 声音配合 | 加速和撞击更有力度 | 已有引擎/风声/boost/撞击/提示的起落同步，轻重分明，连续驾驶不疲劳 | 画面爆发但声音平；重复撞击声堆叠；无法区分推进与碰撞 |

## 演示情境

1. 主片：约 30 秒真实运行，常速进入城市、加速、boost、倾斜弯道、释放与恢复。录制正常追尾镜头，并保留声音。
2. 碰撞补充：分别展示轻擦、持续擦墙、较重撞击，明确是否采用脚本控制。通过真实接触驱动效果，不在录像时间线上假触发。
3. UI 补充：既有排名变化与提示的完整进入/退出；既有主菜单、暂停、设置、结果各展示代表状态。示范段阶段先定 HUD 和一张菜单的通用语言，完整界面覆盖属于扩展阶段。
4. 舒适度对照：关闭/减弱动态后的路线仍可读、事件仍有反馈，控制偏好得到遵守。

## 比较方法

- 基线保留两个层级：任务开始时完整游戏版本，以及当前候选内可独立关闭的诊断效果。不要维护无法组合管理的大量生产开关。
- 资产/灯光/VFX 比较尽量保持输入、时间与镜头一致，报告实际差值。
- 相机或倾斜改变时，旧版与新版的像素/姿态天然不同。比较相同路线区间和驾驶意图，分开说明镜头及几何变化，不制造“精确同镜头”的说法。
- 普通实机实时录像用于速度和音画判断；固定 simulation-time 录像用于细看形态，必须标注，不能作为实时帧率证据。
- UI 用屏幕空间实际尺寸检查，碰撞用连续片段检查。建筑用多视角与移动中的遮挡/切换检查。
- 已有自动化测试不证明艺术品质；每次改动只补充必要的行为/生命周期回归。做完后检查完整场景，不能靠累计通过数量代替成果。

## 性能与稳定性

第一轮提出的目标是当前机器原生 1080p 下稳定达到 60 fps 级别。至少重复测量完整主片区间和碰撞压力区间，记录采样时长、画质、p50/p95/p99、超过 16.7/33.3 ms 的帧比例及可用的 CPU/GPU 测量；报告暖机和首次进入的区别。新旧版本使用相同限制条件，性能测量与录像/编码分开。预算分给城市绘制、阴影/光照、后处理与透明过绘，不能只记录总三角形或粒子数。

必须覆盖暂停/恢复、重开、回标题、自动恢复、boost 能量耗尽、快速重复碰撞、反复进入赛道后的资源回收。若修改道路倾斜/网格，检查实际接触与飞船稳定性。UI 检查常用分辨率、现有键鼠/手柄导航和 reduced motion。新版本的结果重新获取，不继承旧候选的测试/性能数字。

## 品质门槛

阶段 1/2 交付时，负责人对每一行标为“已展示 / 不足 / 未验证”，附最短直接证据。任何核心维度仍明显不足，都不能称完整体验达标。用户认可整体方向后再扩展路线和全部界面；最终艺术接受仍由用户决定。
