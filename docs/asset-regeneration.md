# Asset regeneration and integration

Run these commands from the Vector Rush project root. Blender is expected at `/Applications/Blender.app/Contents/MacOS/Blender`; set `BLENDER_BIN` to use another installed executable. These commands were inspected against the copied source scripts. They were not re-rendered as part of this documentation change.

## Safe entry points

```sh
tools/blender.sh --help
tools/blender.sh hero-v2
tools/blender.sh hero-v2 --preview
tools/blender.sh hero-v2-inspect
tools/blender.sh environment-v2
tools/blender.sh legacy-v1
```

Each operation prints a new `evidence/asset-regeneration/<operation>.*` directory and operates on copied scripts/sources. No operation publishes into Unity. Full hero generation exports `HeroShip.fbx`, writes its editable blend/statistics and renders inspection views. `--preview` reduces render size/views but still rebuilds and exports geometry. `hero-v2-inspect` renders a copy of the frozen blend and never exports an FBX. The environment operation creates required `exports/` and `renders/` directories, builds the complete kit, then runs the FBX audit on those staged exports.

## Paths and dependency status

- **V2 hero:** `ROOT = Path(__file__).resolve().parent`; outputs are alongside the generator. No absolute project paths or external textures are required. The copied frozen FBX is stored in the live Unity Art folder, not alongside the packaged source. Frozen metadata is evidence for that specific export and is not regenerated by the script.
- **V1 hero:** `ROOT = ...parents[1]`; its generator hardcodes `UnityProject/Assets/Resources/Art/HeroShip.fbx` beneath that root. Directly running `SourceAssets/build_assets.py` would replace current V2 with V1. The wrapper copies it into a fresh `SourceAssets/` staging tree first, so that hardcoded destination is isolated.
- **V2 environment:** resolves all paths relative to its script. `build_environment.py` unconditionally executes the now-packaged `rock3_material.py` and requires the selected images under `textures/`. These dependencies are included, so the standard wrapper command uses the self-contained source package. The wrapper checks for the material helper before starting and creates the output directories the generator expects.
- A complete sibling source folder can be selected explicitly without modifying the package:

```sh
VECTOR_RUSH_ENVIRONMENT_SOURCE="$(pwd)/../Vector Rush Review/environment-v2" tools/blender.sh environment-v2
```

- `refine_cliff.py` is a historical partial revision tool. It opens the existing blend, replaces the cliff from a source-code slice and exports only Cliff C. Its statistics still name superseded procedural limestone textures. Do not use it as the canonical clean regeneration chain. `stone_texture.py` also belongs to those rejected procedural material trials.
- The original download API manifest is included as `SourceAssets/environment-v2/textures/Rock3_files-manifest.json`, alongside `Rock3_download-record.json`. The source provenance links to these packaged names; exact original map URLs and SHA256 values remain in the record.

## Review, then copy explicit candidates

Set `candidate` to the exact staging directory printed by the completed operation. Review the renders and geometry/audit reports before replacing runtime assets. Copy only payloads, preserving all existing Unity `.meta` files and their GUIDs.

For an accepted hero candidate:

```sh
candidate="/absolute/path/printed/by/the/hero-v2/operation"
shasum -a 256 "$candidate/HeroShip.fbx"
cp "$candidate/HeroShip.fbx" UnityProject/Assets/Resources/Art/HeroShip.fbx
```

For an accepted environment candidate:

```sh
candidate="/absolute/path/printed/by/the/environment-v2/operation"
for asset in Solstice_TerraceTower_A Solstice_SplitTower_B Solstice_CoastalCliff_C; do
  cp "$candidate/exports/$asset.fbx" "UnityProject/Assets/Resources/Art/Environment/$asset.fbx"
done
for texture in Rock3_CC0_Albedo.jpg Rock3_CC0_NormalGL.png Rock3_DERIVED_MetallicSmoothness.png; do
  cp "$candidate/textures/$texture" "UnityProject/Assets/Resources/Art/Environment/Textures/$texture"
done
```

Reimport and review under the native chase camera after copying. Preserve the imported sharp normals, existing material mappings and V2 nozzle positions. Record the new FBX hash with its review evidence; do not treat the old frozen manifest as verification of a new candidate. These copy commands intentionally replace live payloads and are never run by the wrapper.

## Rock 3 texture chain

The 2K albedo, OpenGL normal and roughness maps are third-party CC0 source images credited to Rob Tuytel / Poly Haven. Their hashes were checked against the packaged download record. The environment's `rock3_material.py` loads those originals directly into Blender with texture scale 4 and normal strength 0.75. It does not generate the packed URP mask.

`Rock3_DERIVED_MetallicSmoothness.png` is supplied separately: RGB = 0, alpha = 1 − source roughness. A standalone mask-generation script is not included; the wrapper preserves the supplied derivative. If recreating it, preserve roughness as linear data, invert its grayscale channel into alpha, keep RGB black, and save an RGBA PNG without color-adjusting the original source. URP imports this mask as non-color, the albedo as sRGB and the OpenGL image as a normal map. The older `Solstice_Limestone_*` maps are retained for historical reproduction only and are not current runtime inputs.
